## AMC OS Review Agent — advisory review

**PR:** branch `proposal/adr-0020-schema-moves-db-roles` (vs `origin/wp4-step15-canonical-data-model`), round 2 · **Step / WP:** none of its own. This is an owner-requested Draft ADR-0020 that collects the items EA-003 §7, EA-005 §9, EA-007 §13 and DA-001 §8 deferred to it (WP4, before Step 16). · **Reviewed at:** 075ef7bb9fa955aac2bf7b50ce67cd5342188bdc

**Verdict (advisory):** BLOCK
All 17 round 1 findings are fixed, but the fixes added one new security gap and one design gap. The `search_path` rule in part 7 still lets a caller redirect audit writes into its own temporary table (I tested this on PG 16.15). The widened tenant-removal procedure would also be stopped by immutability triggers on 8 tables the ADR never mentions.

### Findings
| # | Severity | File:line | Finding | Suggested fix |
| --- | --- | --- | --- | --- |
| 1 | Blocker | ADR-0020:111 (part 7.2) | **New in this round (from the round 1 finding 3 fix).** Part 7.2 sets the rule `SET search_path = pg_catalog, <its schema>` for every SECURITY DEFINER function. When `pg_temp` is not listed, PostgreSQL searches it **first** for tables. The PostgreSQL page the ADR cites ("Writing SECURITY DEFINER Functions Safely") warns about exactly this. I tested it on PG 16.15 with a definer audit-write function written this way, owned by a separate writer role and with PUBLIC execute revoked. The caller ran `CREATE TEMP TABLE audit_event(...)` and `GRANT INSERT` on it to the writer role. After that, the function's unqualified `INSERT INTO audit_event` went into the caller's temporary table. Nothing reached `audit.audit_event`, and no error was raised. A faulty or compromised module could therefore silently drop its own audit records. The same rule covers the import, removal, provisioning and session-ending functions. | Change 7.2 to `SET search_path = pg_catalog, <its schema>, pg_temp` (`pg_temp` explicitly last), and require every table name in these functions to include its schema. Add a case to Validation test 9: a caller-created temporary table with the same name does not capture the write. |
