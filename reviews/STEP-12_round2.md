| 1 | Minor | docs/04_enterprise_architecture/EA-005_multi_tenant_architecture.md:65; database/ddl/DDL-000_core_schema_v0.9.sql:259-279 | The audit import says it "writes the rows and their original hashes unchanged… never recomputes hashes". In DDL-000, the BEFORE INSERT trigger `audit.tg_hash_chain` always overwrites `prev_hash` and `row_hash`. So the import as described cannot work unless the trigger is bypassed or given an import mode, which weakens a tamper-evidence control. There is a second gap: `event_seq` comes from a per-cell sequence (`audit.audit_seq`) and the chain is ordered by `event_seq DESC`. If the target cell's sequence is behind the imported values, the next new audit row sorts before the imported rows, and the chain check fails. G6 and the ADR-0020 row cover only removal, not this import conflict. | Name the trigger conflict and the sequence advance as open points in §2.1 and G6 (DA-001 with ADR-0020).
